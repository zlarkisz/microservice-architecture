# Ролі користувачів та дозволи

## Загальний огляд

E-Commerce система визначає 5 ролей користувачів на основі bounded contexts:
**ProductCatalog**, **SupplyChain**, **Pricing**, **OrderManagement**, **UserManagement**, **ContentManagement**.

Кожна роль дотримується принципу **Least Privilege** — користувач отримує лише той доступ, який необхідний для виконання своїх задач.

---

## Ролі

### 1. Guest (Гість)

Неавтентифікований відвідувач, який переглядає платформу.

**Дозволено:**

- Переглядати каталог товарів та деталі продуктів
- Переглядати ціни та акції

**Заборонено:**

- Оформляти замовлення
- Отримувати доступ до будь-яких персональних даних
- Виконувати будь-які операції запису

---

### 2. Customer (Покупець)

Зареєстрований та автентифікований покупець.

**Дозволено:**

- Оформляти, переглядати та скасовувати власні замовлення
- Переглядати власну історію замовлень
- Редагувати власний профіль, адреси та налаштування
- Переглядати каталог товарів та ціни

**Заборонено:**

- Переглядати замовлення або персональні дані інших користувачів
- Змінювати каталог товарів або ціни
- Отримувати доступ до ланцюга постачання або адміністративних функцій

---

### 3. Vendor (Постачальник)

Постачальник, відповідальний за надання товарів на платформу.

**Дозволено:**

- Додавати та редагувати власні товари в ProductCatalog
- Управляти власними поставками в SupplyChain
- Переглядати рівні залишків для власних товарів

**Заборонено:**

- Переглядати товари або дані постачання інших вендорів
- Отримувати доступ до замовлень або персональних даних покупців
- Змінювати ціни (управляється окремим сервісом Pricing)
- Отримувати доступ до ContentManagement

---

### 4. Content Manager (Менеджер контенту)

Співробітник, відповідальний за редакційний контент на платформі.

**Дозволено:**

- Редагувати описи товарів, зображення та категорії в ContentManagement
- Публікувати та знімати з публікації контент
- Переглядати каталог товарів (лише читання)

**Заборонено:**

- Отримувати доступ до даних замовлень або фінансової інформації
- Отримувати доступ до даних ланцюга постачання
- Змінювати ціни або наявність товарів

---

### 5. Admin (Адміністратор)

Системний адміністратор з повним доступом.

**Дозволено:**

- Отримувати доступ до всіх сервісів та даних системи
- Управляти обліковими записами користувачів та призначати ролі
- Переглядати та управляти замовленнями, товарами, постачанням, цінами та контентом

**Особливі обмеження:**

- Всі дії Admin записуються в **audit log** (хто, що і коли зробив)
- Не може назавжди видаляти записи фінансових транзакцій — лише читання фінансової історії
- Призначення ролей вимагає кроку підтвердження для запобігання випадковому підвищенню привілеїв

## Додаткові загальносистемні обмеження

Ці обмеження діють незалежно від ролі:

**Rate Limiting** — обмеження кількості запитів на хвилину для запобігання зловживанням:

- Guest: 60 запитів/хв
- Customer: 300 запитів/хв
- Vendor / Content Manager: 300 запитів/хв
- Admin: 600 запитів/хв

**Захист від Brute Force** — після 5 невдалих спроб входу обліковий запис тимчасово блокується на 15 хвилин. Підозрілі IP-адреси позначаються та можуть бути заблоковані.

**Термін дії токенів** — access token діє 15 хвилин. Для оновлення використовується refresh token (дійсний 30 днів). Після закінчення сесії потрібна повна повторна автентифікація.

**Audit Logging** — всі операції запису (створення, оновлення, видалення) логуються із зазначенням `userId`, `role`, `action`, `timestamp` та `affected resource`. Дії Admin логуються завжди, незалежно від типу операції.
